Implement issue #125 in nicolovejoy/raconte: library entry rows in the current
week show the time of day, not just the date.

Owner's words (smoke, 2026-08-30): "add time to the minute for entries in the
current week I think. that's helpful." The problem: an entry recorded today and
one from three days ago both read as a bare date, and several readings in one
day — the common case — are indistinguishable.

THE CODE, so you start in the right place:

- The row's date string is `EntryListItem.formattedEffectiveDate()`
  (Raconte/Library/EntryListItem.swift:205): if `originalDate` (a backdate,
  type PartialDate) is set it formats THAT; otherwise `capturedAt`, day only.
- That function is SHARED by four surfaces: the library row (LibraryView
  `dateText`), CaptureReceipt, EntryInfoSheet, EntryDetailView. #125 is scoped
  to the LIBRARY ROW ONLY — do not change what the other three render. Add a
  parameter or a sibling accessor; do not fork the logic into the view.

DECISIONS, pinned:

1. Time appears ONLY on the `capturedAt` branch. A backdated entry shows a
   user-authored date; a PartialDate has no time and inventing one from
   `capturedAt` would lie about the reading it claims to date. Backdated rows
   are unchanged even inside the current week.
2. "Current week" = the calendar week containing now IN America/Los_Angeles
   (repo rule: UTC at rest, Pacific on display; never bucket by UTC). Build it
   with a Calendar whose timeZone is America/Los_Angeles and
   `dateInterval(of: .weekOfYear, for: now)`; membership is
   `interval.contains(capturedAt)`. Do not hand-roll day arithmetic.
3. Format: keep the existing date, append the time — e.g. "Aug 31, 9:41 PM"
   via `time: .shortened` (LibraryView:512 already uses exactly this pair for
   `recordedDateText`; match it). State the final format in the PR body for
   owner smoke.
4. Out of scope: #83 confirmation behavior, the parked month-formatter cache,
   any change to month/year grouping, and the detail/info/receipt surfaces.
