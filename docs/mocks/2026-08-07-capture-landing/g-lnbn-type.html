What each control asks

  • Mixed page — the normal case: one unattributed opener (before the first voice marker) then alternating LN/BN of ordinary length. Read a full screen of it on each side. This is the only question that matters; the rest are tie-breakers.
  • Short turns — five one-line exchanges. Serif at 17 pt gets a lot of vertical air per turn; the prefix repeats fast enough to become texture.
  • Long passage — one long BN paragraph. This is where BN-italic is actually tested: a whole screen of italic is the load, not two lines of it.
  • Live while recording — the same prose in the near-black capture screen with the thumb bar, so the face is judged where it is read at arm's length.
  • Prefix — shipped is the prose face, semibold, secondary. The alternative keeps the prefix inline but sets it as a letterspaced sans micro-cap in the accent, so it reads as a label rather than as a word in the sentence.
  • BN italic off — what the page looks like if the print-vs-cursive signal moves entirely onto the prefix.

Known bias in the comparison

  • New York has a smaller x-height than SF at the same point size, so the sans side is set one point smaller (16 vs 17) to match apparent size. If you want the literal same-point comparison, that is a one-line change.
  • SF italic is an oblique. As the print-vs-cursive stand-in it is weaker than New York's true italic — check this on Long passage before deciding, because it is the strongest argument the serif has.

Palette — derived, not picked

One fact worth weighing

The app icon's wordmark is set in a serif — letterspaced lowercase, cream on navy. Picking sans for the transcript would make the reading surface disagree with the mark. That is not decisive; it is a cost.
